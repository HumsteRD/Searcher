# Threat Scanner — состояние проекта

Windows-утилита проверки системы на угрозы. C++20 / Qt 6 (vcpkg, x64-windows),
CMake, MSVC. Интерфейс: русский и английский. Версия задаётся в одном
месте — `project(ThreatScanner VERSION x.y.z)` в `CMakeLists.txt`.

Репозиторий: https://github.com/HumsteRD/Searcher. Коммиты — от
`HumsteRD <330619670+HumsteRD@users.noreply.github.com>` (почта аккаунта
Claude с GitHub не совпадает).

## Сборка и запуск

`cmake` не в PATH — он идёт с Visual Studio:

```
"C:/Program Files/Microsoft Visual Studio/18/Community/Common7/IDE/CommonExtensions/Microsoft/CMake/CMake/bin/cmake.exe" --build C:/test/ts2/build --config Release
```

vcpkg: `C:/dev/vcpkg`, toolchain уже в кэше сборки. Базы сигнатур в git
не хранятся: `python tools/sigdb/fetch_signatures.py` кладёт их
в `res/signatures`, сборка копирует рядом с exe.

- Окно запускается без прав администратора (манифест `asInvoker`).
- LNK1104 при линковке — приложение запущено и держит exe. Трей по
  умолчанию включён, крестик прячет окно: `taskkill /IM ThreatScanner.exe /F`.
- Консоли нет, сообщения Qt — в `%TEMP%\ThreatScanner-debug.log`.
- `ThreatScanner.exe --shots <папка>` — скриншоты всех страниц на демо-данных
  (темы × языки × три ширины окна). Интерфейс проверять только так —
  все страницы разом, а не один экран.
- Консольные проверки: `engine_selftest` (ядро на нейтральных данных),
  `engine_scan <путь>` (вердикт по файлам/папке), `scan_cli` (полная
  быстрая проверка без интерфейса), `dynmon_test`, `sandbox_test`, `ipc_test`.

## Выпуск версии

1. Поднять версию в `CMakeLists.txt`.
2. `powershell -ExecutionPolicy Bypass -File tools/package.ps1` — собирает
   Release, раскладывает `dist/ThreatScanner`, собирает Inno Setup
   (`installer/ThreatScanner.iss`) в `release/ThreatScanner-Setup-x.y.z.exe`
   и печатает SHA-256.
3. Релиз на GitHub с тегом `vx.y.z`, файлом установщика (в имени `setup`,
   расширение `.exe`) и строкой `SHA-256: <hex>` в описании.

`Updater` смотрит `releases/latest`: сравнивает версию из тега, качает
установщик, сверяет размер и SHA-256 и запускает его с `/SILENT`;
установщик после тихой установки снова запускает программу. Автоустановка
в настройках по умолчанию выключена — тогда программа только предлагает
обновиться.

Релиз `signatures-latest` (пре-релиз, чтобы не стать «последним») держит
`base.tsdb`; его раз в неделю пересобирает `.github/workflows/signatures.yml`.
Правила YARA-Forge и свежие хэши MalwareBazaar `SignatureUpdater` берёт
напрямую у источников.

## Устройство

- `src/engine` — ядро поиска по файлам, без Qt.
  - `HashDatabase` — формат `.tsdb` (описан в `tools/sigdb/build_sigdb.py`):
    отсортированные первые 8 байт SHA-256 + семейство. Встроенная база
    и обновления из `%ProgramData%\ThreatScanner\signatures` объединяются.
  - `YaraEngine` — libyara, правила YARA-Forge core/extended. Правила
    компилируются только из исходников: скомпилированный `.yarc` из общей
    папки не грузить — туда может писать любой пользователь.
  - `Unpack` — ZIP (в т.ч. ZIP64 и SFX), PyInstaller (CArchive + PYZ).
  - `TrustVerifier` — Authenticode, встроенная подпись и каталоги.
  - `ScriptHeuristics` — эвристики по языку скрипта (PowerShell, Batch,
    WSH, Python; JS — только с признаками WSH). `node_modules` и
    `site-packages` не проверяются.
  - `FileAnalyzer::Decide` — политика вердикта (ниже), `FileWalker` —
    обход дисков с исключениями, `ScanPipeline` — параллельная проверка.
- `src/core` — модули проверки (`Files`, `Processes`, `Autoruns`, `Tasks`,
  `Services`, `Network`), действия над угрозами, карантин, наблюдение
  за поведением, песочница, служба.
- `src/ipc` — помощник с правами администратора и канал к нему.
- `src/app` — окно, настройки, история, обновления, язык.
- `src/ui` — дизайн-система: `Theme` (палитры и таблица стилей),
  `Widgets`, `Icons`, `Shell` (боковое меню), `FramelessWindow`.
- `src/pages` — страницы; порядок — `MainWindow::PageId`.

### Политика вердикта — не ослаблять

Ложное срабатывание на легитимной программе дороже пропуска: после него
инструменту перестают верить.

- Совпадение хэша с базой — угроза всегда.
- У правил YARA есть сила (`Classify::RuleStrength`): индикаторы сами по
  себе угрозой не бывают, слабые правила требуют подтверждения.
- Файл, подписанный доверенным производителем (точный список в
  `TrustVerifier`), по правилам YARA не помечается; при любой другой
  действительной подписи остаются только правила с оценкой от 90.
- Записи MalwareBazaar без названия семейства берутся, только если файл
  опознают ≥10% антивирусов VirusTotal — иначе в базу попадают
  присланные «на всякий случай» чистые программы.
- Файлы больше 64 МБ: хэш считается потоком, YARA смотрит первые 64 МБ.

Проверено без ложных срабатываний: System32, Program Files (x86), AppData,
Downloads, ProgramData, второй диск, все службы и драйверы, задачи,
автозапуск, процессы, сеть. Любую правку ядра прогонять через
`engine_scan` на этих папках.

### Причины находок

Ядро пишет причины кодами (`код\tаргумент...`), по-человечески их
формулирует интерфейс (`src/app/Texts.cpp`). Код без перевода показывается
как есть — это видно сразу, а не теряется.

### Язык

Строки в коде — английские, через `TR("...")` и `TRN(...)` (числительные:
в русском три формы, «21 процесс», но «11 процессов»). Перевод:

```
python tools/i18n/extract.py        # недостающие ключи → build/i18n-missing.json
# дописать переводы в tools/i18n/ru.json
python tools/i18n/extract.py --gen  # пересобрать src/app/LangRu.cpp
```

При смене языка страницы пересоздаются.

## Грабли, на которые уже наступали

- **`winId()` в `nativeEvent` создаёт окно** → рекурсивное `CreateWindowEx`,
  ошибка 0x57 и зависание. Только `internalWinId()`.
- **Нативную настройку окна нельзя делать в конструкторе** — платформенного
  окна ещё нет. Только в `showEvent`.
- **Все указатели-члены инициализировать `nullptr`**: `changeEvent` и подобные
  приходят во время работы конструктора.
- **Исходники в UTF-8, компилятор с `/utf-8`.** Невидимые символы (RTLO и т.п.)
  писать кодом: `static_cast<wchar_t>(0x202E)`, а не литералом.
- **C++ и регулярки не писать через bash heredoc/python** — экранирование
  обратных слэшей ломается. Только инструменты Write/Edit.
- **Пересборка содержимого страницы**: старые виджеты удаляются отложенно
  и успевают попасть на скриншот. `Ui::clearLayout` + `sendPostedEvents`
  с `DeferredDelete`.
- **Области прокрутки**: `setAutoFillBackground(false)` у содержимого,
  прозрачный `viewport` в таблице стилей — иначе тёмный прямоугольник
  в светлой теме.
- **Длинный текст в карточках** — `Ui::breakable()` и `FlowLayout` для
  рядов кнопок, иначе панель обрезается на узком окне.
- **Порядок правил в таблице стилей важен**: `QListWidget` после `QListView`.
- **Отключать сигналы по сохранённому `QMetaObject::Connection`**, а не
  `disconnect()` с шаблоном — Qt ругается и отключает лишнее.
- **Ключи настроек — с префиксом `v2/`**: значения первой версии имеют
  другой смысл.
- **Порядок `MalwareClass` (`Verdict.h`) и модулей `ScanConfig` — это
  протокол** с помощником и службой: менять только добавлением в конец.
- **Пути из `QFileDialog` идут с прямыми слэшами**, из обхода каталога —
  с обратными. Перед сравнением нормализовать.
- **Qt не читает ICO с PNG-записями** — иконки в интерфейсе рисуются кодом
  (`Icons`), `app.ico` — только для exe и установщика.
- **Рекурсивное наблюдение за каталогом не доходит до `%TEMP%`.**
  `ReadDirectoryChangesW` с `bWatchSubtree = TRUE` на `%LOCALAPPDATA%`
  не даёт ни одного события из `%LOCALAPPDATA%\Temp`. Вложенные корни
  не схлопываем, повторы гасит окно склейки в `FileActivityWatcher`.
- **Синхронный ввод-вывод на одном дескрипторе идёт строго по очереди.**
  Дуплекс на одном дескрипторе канала — только через `FILE_FLAG_OVERLAPPED`
  с отдельным событием на каждое направление (`PipeChannel`).

## Разделение прав

Интерфейс работает от пользователя. Всё привилегированное — в
`ThreatHelper`, который поднимается через UAC и живёт, пока открыт канал.

- Имя канала случайное на каждый запуск, `FILE_FLAG_FIRST_PIPE_INSTANCE`.
- Список доступа: текущий пользователь, SYSTEM, администраторы.
- Подключившийся проверяется по учётной записи и пути к образу по одному
  дескриптору процесса. Олицетворением проверять нельзя — оно работает
  только после первой команды клиента.
- **От процесса того же пользователя это не защищает и не может.**
  UAC не граница безопасности — писать в интерфейсе обратное нельзя.

Через помощника идут: проверка целиком (`ScanService`; настройки едут
с командой `start_scan`), действия над угрозами, изменение карантина,
карантин отдельного файла (`quarantine_file`), песочница, включение
компонента Windows Sandbox (`sandbox_enable`, DISM), управление службой.
В опросе состояние отправляется последним, после статистики.

Проверка одного файла (перетаскивание, меню проводника, мониторинг
загрузок) идёт без помощника — `LocalCheck`, прав не требует.

## Служба фоновых проверок

`ThreatService.exe` (SYSTEM) — проверки по расписанию при закрытом окне.
**Командного канала у службы нет, и это главное решение**: постоянно
работающий процесс с полными правами не должен принимать команды.
Настройку читает из `HKLM` (`ServiceConfig`), результаты пишет
в `%ProgramData%\ThreatScanner\service-scans.json`, окно подхватывает их
в историю (`ScanHistory::importServiceScans`). Ставится и снимается через
помощника (сама установка — код службы, `--install`), управление —
в настройках.

Не проверено вживую: установка службы и срабатывание расписания.

## Анализ поведения (Windows Sandbox)

- `BehaviorMonitor` — запуск цели в job-объекте, дерево процессов,
  наблюдатели файлов, реестра и сети. Вне песочницы для подозрительного
  файла его звать нельзя: он запускает файл там, где его позвали.
- `SandboxEnvironment` — доступна ли песочница и что мешает (домашняя
  редакция / компонент не установлен / виртуализация выключена).
  `ProductName` на Windows 11 врёт, редакция уточняется по номеру сборки.
- `WsbGenerator` — конфигурация: `C:\sample` и `C:\agent` только чтение,
  `C:\report` запись; сеть, буфер обмена, устройства выключены.
- `ThreatAgent` — уезжает в песочницу, пишет отчёт JSON и гасит машину.
- `SandboxSession` — сеанс целиком; рабочая папка с копией образца
  удаляется в любом случае.
- `BehaviorVerdict` — улики с весами, пороги 6 и 10. Итог расходится
  из `BehaviorPage::publish`: угроза по файлу на хосте (путь — выбранный
  пользователем, не `C:\sample\...`), запись в историю, сохранённый отчёт.

Правила:

- **Пустой результат — не справка о безопасности**, текст так и говорит.
- **Образец, который не запустился, не судят вовсе.**
- Отчёт, открытый из файла, в угрозы и историю не попадает.

**Машина разработки — Windows 11 Домашняя, песочницы на ней нет.** Живой
прогон «команда → WindowsSandbox.exe → отчёт → страница» не выполнялся.

## Что не проверено вживую

- Действия через помощника (UAC): карантин, удаление, служба.
- Windows Sandbox (нужна Pro/Enterprise).
- Установка из установщика и автообновление целиком.
- Детект на реальных образцах у пользователя: сейчас база — около миллиона
  хэшей MalwareBazaar и ~5000 правил YARA-Forge core (+ extended).
